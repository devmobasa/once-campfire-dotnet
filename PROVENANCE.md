## Local adaptations

The imported tooling is adapted for the .NET application, rootless containers and validated measurements. The groups below identify these adaptations and their current purpose. Comments link to pinned upstream design documents or explain the technical choice directly. `reference-tools/db-rollback/rollback.rb` and `reference-tools/db-rollback/scenario.rb` were retired because migration and Rails rollback are outside this fresh-install rewrite's scope. Their original checksum entries remain as provenance. Verification reports their intentional removal and the recorded adaptations.

Companion files include capture cancellation/error/security-header/cookie/image tests, the optional loopback protected-token resolver client, and an error-response clone drain. The drain lets Chromium finish unconsumed error bodies before the harness advances its paused clock; the original response, status, headers and readable body remain unchanged, and drain failures fail readiness. The pinned `parity/docker/reference.Dockerfile`, upload-validation and CPU-accounting modules under `bench/loadgen/src/`, and C# image, seed, resume, metrics and trace helpers under `bench/` are also companion files. Their operating contracts are documented in [reference testing](docs/development.md) and [benchmarks](docs/benchmarks.md). Preparation changes only disposable synthetic credentials and opaque signed identifiers; it does not establish production database interoperability. Native harness acceptance requires the full browser gates, independently of focused harness tests.

The network capture also distinguishes WebKit's unloaded, error-free `preload=none` video preview receipts from real HTTP responses. Every unmatched non-HTTP receipt and genuine network failure still fails capture. The companion `wire_receipts.ts` records target-owned redirect headers when WebKit omits them from its protocol receipt; native security assertions require a fresh, unambiguous, single-use match of method, URL, status and Location. The companion `test/phantom.test.ts` and `test/wire_receipts.test.ts` preserve wrong-record, real-resource, missing-header and stale/ambiguous-evidence failures. A bounded response snapshot checks every capture error before selecting the latest successful response per request.

Firefox text-frame capture decodes the pinned Playwright transport's byte strings as strict UTF-8 before Cable logging and readiness checks. Other engines retain their decoded text; malformed Firefox input remains a capture error. The companion `test/frame_error.test.ts` covers transport representations and error recording; `test/frame_error.browser.ts` checks actual Firefox against independently emitted and received WebSocket bytes. Page errors retain their name, message, stack and string value, including empty errors. These capture repairs do not change application messages or vendored Turbo.

Network comparisons treat Vary as a deduplicated field-name set while retaining missing or additional fields. The native signed-out room contract checks the original destination, exact returnUrl, final sign-in documents and ARIA, and response evidence before accepting the documented challenge header difference. Older captures without raw Location headers must supply the exact captured redirect block; this qualification is retained in the comparison receipt. New captures retain raw Location too. Wrong destinations, documents, headers and ambiguous evidence remain differences.

`parity/.gitignore` and `reference-tools/.gitignore` retain required upstream `bin/`, `.env.reference` and `storage/` fixtures. These fixtures and `vectors/storage/` match their recorded upstream checksums.
